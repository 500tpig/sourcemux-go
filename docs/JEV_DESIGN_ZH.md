# JEV 研究模式接入设计

采用调研中的方案 B：显式开启 JEV 研究循环，默认固定流程保持现状。依据是 [本地调研](SMARTSEARCH_JEV_RESEARCH_ZH.md) 和 smartsearch 提交 `1969e4fa32a74d0d48b2c752afbadf496e71ef6e` 的 `jev.py`、`jev_search.py`。本次不引入桌面管理、持久健康记录或正文过滤。

## 调用与数据流

CLI `research`、`smart-answer` 增加 `--mode fixed|jev`；MCP `research_run`、`smart_answer` 增加同名 `mode` 参数。省略时使用 `fixed`。共同进入 `ResearchExecutor`，JEV 模式在独立文件中执行。

每轮从已配置的搜索渠道、计划查询、固定缺口模板及已发现 URL 构造候选。JEV 给候选打分，本地按 0.5 阈值选择有限动作；没有合适动作就停止。搜索复用现有 provider 适配器，指定渠道时只执行该渠道；下一轮可以选择其他渠道。抓取复用现有路由，最多提供五个已知 URL。

只有抓取成功且非空的正文预览参与充分性评估；搜索摘要仅用于发现链接。判断有用性、充分性及五类缺口，充分性达到 0.75 且有正文时提前停止。查询、渠道、URL 的相同组合只执行一次。网页内容始终作为数据，不能改变候选、预算或配置。

## 配置与接口

v1、v2 配置均增加顶层 `jev` 对象：`apiURL`、`apiKey`、`model`、`timeoutSec`。默认地址为 `https://api.typesafe.ai/v1`，模型为 `jev-latest`，单次判断默认 15 秒。未启用 JEV 模式时不请求该服务；显式启用但缺 Key 时返回配置错误。

独立客户端向 `/systemone` POST `model`、`state`、`questions`，使用 Bearer 认证。只读取已发送问题 ID，拒绝缺项、布尔值、非数字、错误类型及越界概率。429/529 最多尝试三次，退避也消耗单次判断与任务预算。记录阶段、耗时、token 用量及安全错误信息。

## 预算与返回

| 深度 | 轮数 | 每轮动作 | 总时限 |
| --- | --- | --- | --- |
| quick | 2 | 1 | 45 秒 |
| standard | 3 | 2 | 120 秒 |
| deep | 5 | 3 | 300 秒 |

调用方更短的截止时间优先。每个动作有单次超时，总动作数不超过轮数乘每轮上限，抓取还受 `max_fetches` 限制。JEV 模式不额外执行 map/crawl。smart-answer 的 JEV 模式使研究与综合共用上述总截止时间。

研究包增加可省略的 `jev` 记录，包括判断状态、缺口、已读引用、逐轮动作、调用用量和停止原因。运行中判断失败保留已有证据，状态设为 `unknown`，以 `judgment_unavailable` 停止，不伪造充分性。没有新证据、候选耗尽、超时或次数耗尽分别记录。最终综合只能引用已读 URL，并明确未知或不足；概率不代表答案正确率。

JEV 模式改为分页阅读：每个 URL 只抓取一次，任务内最多保留该来源 75,000 字符。每次读取约 5,000 字符，优先在段落边界停止，并保留约 200 字符的重叠。每个来源从已读范围内累计选择最多 2,000 字符的相关原文摘录，记录 Unicode 字符的起止位置；不额外调用模型生成摘要。

抓取的来源先读取首段，再评估累计证据。证据不足时，在已抓取来源之间依次读取后续分页，每次更新摘录后再判断；充分、判断失败、正文读完或预算耗尽时结束分页。quick、standard、deep 分别最多读取 2、6、15 页，首段也计入。分页不重复消耗抓取次数，所有判断仍受统一截止时间限制。全文未读完、保留上限截断和摘要省略分别标记。

JEV 判断与最终综合共享同一份摘录视图，整体证据仍限制为约 20 KB。综合输入不再混入搜索摘要、未读候选和启发式 confirmed_facts。fixed 模式保留现有行为。问题及证据片段会发送给 TypeSafe，供应商 Key 不进入 state 或 trace。

## 实施与验证

先实现协议与配置，再接入研究循环和两个入口，最后补文档与回归检查。自动测试只用本地 HTTP 服务和 fake。协议测试覆盖非法概率、未知 ID、重试和超时。流程测试覆盖候选白名单、提前结束、无新证据和失败保留资料。另检查抓取预算、默认模式、入口透传、配置迁移和引用输出。

本次分页版本已通过 gofmt、`go test ./...`、`go vet ./...`、`go build ./...` 和 `git diff --check`。新增验收覆盖后续分页命中、累计摘录与原文位置、单 URL 只抓取一次。另测充分后停止、跨来源继续阅读、判断失败及预算耗尽保留证据。

同题真实复测已完成：两份 Go 官方正文分别读取 4 页、2 页，累计摘录为 1,969、1,975 字符。JEV 共调用 7 次，最终以 `sufficient` 停止，综合模型返回答案并说明未读完的限制。这个样本证明调用链可以分页继续阅读，不代表所有问题的摘录质量。

真实服务已完成单题流程测试，费用和概率校准未评估。实现采用顺序执行动作，保留现有适配器内部重试；动作上限不等同于 HTTP 请求数上限。具体使用及输出说明见 [JEV 使用说明](JEV.md)。
